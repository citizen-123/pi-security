- [x] 2.2 Candidate normalization (`normalize_candidates.py`). Done: `src/contract/candidates.ts`, plus `src/contract/python-json.ts` for Python int/float parsing, `json.dumps`, float `repr`, code-point ordering, and `repr()`. Passes all 24 normalize cases (8 added for Python semantics); every rejection matches Python's reason. Output writing stays with the finalizer port and the runtime's artifact writer. Windows-only branches are ported but untested here.
- [x] 2.3 Git-aware inventory and diff file lists (`generate_in_scope_files.py`, `workbench_target.py` fixed-argument git), plus the working-tree snapshot commit (D14) with tests that the user's index, branch, and stash are untouched. Port done: `src/target/git.ts` and `src/target/inventory.ts` pass all 15 inventory cases (6 added for raw names, UTF-16 binaries, symlink changes, suffix rules, unnormalized scopes, and byte ordering); every rejection matches Python's reason. Done: `src/target/snapshot.ts` snapshots the working tree without running repository-configured filters, verified by `tests/working-tree-snapshot.test.mjs` (untouched index, branch, stash, status, refs, and files; exact tree contents; per-run and deterministic commits; equivalence with the local-patch inventory; unborn HEAD).
- [x] 2.4 Finalizer, manifest sealing, schema validation, SARIF, and exports (`finalize_scan_contract.py`, `validate_scan_contract.py`). Done: `src/contract/` ports canonical JSON, the schema validator, SARIF, CSV, contract validation, draft recovery and envelope population (`recovery.ts`), scan-local reads and writes (`scan-files.ts`, `scan-writes.ts`), and sealing, exports, and contract validation (`finalize.ts`). All 12 finalize, 27 export, and 3 validate cases pass, plus every recorded vector for these functions (recovery vectors also check the arguments they change). `tests/scan-writes.test.mjs` and `tests/finalize.test.mjs` run hostile filesystem and tamper scenarios through Python and the port and require identical outcomes and trees. Done: `src/contract/report-projection.ts` matches 120 report and 89 `merged_root_cause` vectors byte for byte, including `tests/test_report_projection_edges.py` cases for Python whitespace, Unicode digits, `bool` line numbers, and deep report grouping.
- [x] 2.6 Preflight (`config_preflight.py`) and the patch-risk validator in `skills/assess-patch-risk`. Done: `src/config/preflight.ts` (with a port of Python 3.13's non-strict `realpath`) passes 14 preflight cases (11 added for symlinked, dangling, looping, absolute, and repeated working directory links, file targets, and malformed checks). `src/contract/patch-risk.ts` passes all 11 patch-risk cases and 53 vectors from `tests/test_patch_risk_edges.py`, messages included. Its reader uses `src/contract/json-loads.ts`, a port of Python 3.13's `json.loads` (exact `JSONDecodeError` messages and positions, duplicate-key hook, NaN/Infinity, the 4300-digit integer limit), checked against the interpreter on every prefix and single-character edit of its seed documents. One shared difference is documented there: JavaScript iterates array-index keys first. Every curated parity case and vector now has a TypeScript port.

## 3. Runtime foundation

- [x] 3.1 `src/durable/`: the adapter module, exact version pin, Harness open/close, run lock, and `0700`/`0600` run directories. Done: `pi-durable`, `chord`, and `pi-ai` are pinned at `1.4.0`, and the `pi-coding-agent` dev dependency moved from `^0.81.0` to exactly `1.4.0` (same package; `ModelRuntime` needs the 1.4.0 line; no existing test changed outcome). `src/durable/run-directory.ts` resolves the state directory and creates `0700` directories and a `0600` `run.sqlite` (its WAL files inherit the mode); `src/durable/run-lock.ts` is an operating-system lock through SQLite (see D2); `src/durable/harness.ts` opens lock, storage, and Harness in order and closes in reverse. `tests/durable-run.test.mjs` covers permissions, reopen, refused symlinks, locks held by live and killed processes, and eight processes racing for one lock.
- [x] 3.2 Confined environment: port `execution-boundary.ts` rules into an `ExecutionEnv`; run durable's `registerEnvConformance` plus escape tests (symlink, `..`, absolute, fd swap). Done as `ConfinedRoot` plus the `ConfinedEnv` adapter (D7). `tests/confined-env.test.mjs` covers escapes through `..`, absolute paths, Windows forms, symbolic links to files and directories inside and outside the root, dangling links, the scan scope, and a symlinked root; refused writes, temporary files, watching, and `exec` with nothing changed on disk; a reader racing a process that swaps a directory for a link (never outside content); and permitted reads identical to `NodeExecutionEnv`. The conformance suite was replaced by that differential test (see D7); fixer writes move to section 5.
- [x] 3.3 Package tools (`list_files`, `read_source`, `search_source`, `git_metadata`, `get_context`) and per-role `report_*` tools writing session-scoped result documents. Done: `src/durable/scan-tools.ts` and `src/durable/scan-documents.ts`. Source tools read only through `ConfinedRoot` (byte-ordered listings without `.git` or links, UTF-8 line reads of at most 1000 lines, literal search that skips non-text files). `report_threat_model`, `report_candidates`, `report_reduction`, `report_validations`, and `report_attack_paths` take the existing role schemas, record to `security.result/<conversationId>`, and terminate the run; `validateRoleResult` re-validates for admission. `tests/scan-tools.test.mjs` drives a faux-model worker on a real Harness through every tool, refused escapes and the absent built-in `read` included, a rejected report, and a recorded one.
- [x] 3.4 `security.worker` task and role configuration, including the resolved-agent check (D7). Done: `src/durable/worker.ts`. `open` creates the task-owned conversation configured with the role's model, thinking level, instructions, and exact tool list; `run` submits with `requestId: worker:<taskId>`, then admits the recorded result only when the conversation's resolved agent (`harness.conversation(id).agent()`, injected) offers exactly the role's tools and model with nothing extra callable or deferred, and the payload re-validates. `tests/worker-task.test.mjs` covers completion, a model that never reports, drift, and a restart mid-request that resumes the same single conversation. TOML-defined roles follow in 3.5.
- [x] 3.5 Configuration: TOML resolution and roles; `ModelRuntime` wiring behind the redacting `Models` decorator; reject inline credentials. Done: `src/config/run-config.ts` (precedence, `[scan]`, `[execution]` with durations and `max_cost`, `[roles.<id>]`, `[deep_scan]`, `[remediation.checks]`; inline and profile credentials rejected), `src/durable/models.ts` (`ModelRuntime` over Pi's agent directory, role keys in memory, the redacting decorator), and `src/durable/roles.ts` (worker roles with Pi's default model as fallback). `tests/run-config.test.mjs` includes a stub provider whose 401 echoes the key: the stored error is redacted and no run file holds it, while the normal path answers.
